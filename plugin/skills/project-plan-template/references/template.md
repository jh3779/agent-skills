# 기획 템플릿 (발표 역산)

필수 절은 번호 앞에 ★. `scripts/plan_gate.py`가 ★ 절의 존재를 확인한다(제목에 절 이름이 들어 있어야 한다).

## 0. ★ 한 장 요약
- **한 문장 결론**: "이 ○○는 ○○를 하고 ○○는 하지 않는다."
- **하는 일 / 하지 않는 일**: (3개씩)
- **성공 기준 요약**: 가치 지표 · 목표 · 측정 시점
- **발표에서 보여 줄 결과 장면 3개**: (11절과 같은 내용)

## 1. 문제 정의
- 사용자(직무·사전지식) / **구체 장면 1개** (숫자·시간이 있는 장면) / **긴박함 장치**(기한·비용) / 결핍 / 안 하기로 한 것
- 이 장면이 발표의 첫 장이자 마지막 회수 대상이다.

## 13. ★ 도메인 이해
- [ ] **용어표**: 처음 보는 사람이 막히는 용어(규제 기관·문서 이름·업무 단계)를 한 줄씩 푼다.
- [ ] **업무 흐름**: 사용자의 하루/한 주 — 누가·언제·무엇을·어느 시스템으로, 시간 제약(예: 5영업일)이 어디서 걸리는지.
- [ ] **원문 근거**: 규정·사례 링크(확인 못 한 것은 ⬜).
- [ ] **실무자 확인 슬롯**: 인터뷰 1~2명의 날짜. 슬롯이 없으면 범위 제외 결정(이유·말할 문구)으로 기록한다(가치 미측정의 직접 원인이 된다).
- [ ] **일별 시나리오 표**: 사람이 하는 일 / 도구가 하는 일 / 도구가 하지 않는 일 / 산출물. 도구가 못 찾았을 때의 대체 절차와 **희소 사례 시나리오** 포함.

## 14. ★ WBS · 역할(RACI)
| # | 작업 | 담당 | 기간 | 산출물 | 완료 기준(재현 가능한 명령·수치) | 의존 | 위험 |
|---|---|---|---|---|---|---|---|
- 최상위 묶음: 정의 → 수집 → 정리 → 학습 → 평가 → 배포 **+ 운영·프로세스·발표·사용자 검증**.
- RACI는 작업 영역별 R(실행)·A(최종 책임)·C·I. **담당이 없는 영역은 "미지정"으로 둔다 — 빈 칸이 위험 신호다.**
- 계획 담당과 실제 변경(날짜·근거)을 같이 적는다. 개인별 투입 시간은 기록할 수 있을 때만 적는다.

## 15. ★ 시간 예산
- [ ] 단계별 계획 기간과 **Exit Criteria**(재현 가능한 명령·수치).
- [ ] **우선순위 N단계 + 포기 순서**("1~3만 있어도 데모").
- [ ] **버퍼 20%**, 확장 상한(핵심 완성 후 N일, **발표 D-3부터 신규 기능 금지**).
- [ ] **외부 입력 의존 작업**의 마감 2일 전 중간 점검과 대체안(예: 마감 연장·표시 범위 축소·미측정으로 보고. **평가 정답을 AI로 대신 만들지 않는다** — 프로젝트 규칙이 막는 경우가 많고, 이번 프로젝트의 AI 표시는 사용자가 승인한 한시 예외였다).
- [ ] 주 1회 **계획 대비 실제** 갱신(단계별 계획·실제·차이·원인). 사후 복원보다 중간 기록이 정확하다.

## 16. 희소·경계 사례 평가 계획
- [ ] 평가 계획에 층화 분석 한 줄: "무엇으로 나눌 것인가(예: 정답의 부품 라벨 카드 수), 구간 기준, 지표, 판단 규칙(기준 폭)".
- [ ] **구간 기준은 결과를 보기 전에 고정**하고 사후 분석이면 튜닝에 쓰지 않는다. 구간이 작으면 신뢰구간을 같이 적고 "결론이 아니라 관찰"이라고 쓴다.
- [ ] 실패하는 질문의 공통점(정보량 없는 질문 등)을 눈으로 확인한 뒤 정량 분류는 사람이 한다.
