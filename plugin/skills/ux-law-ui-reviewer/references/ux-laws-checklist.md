# UX 법칙별 체크리스트

> SKILL.md 부록 A와 같은 내용. 스킬은 SKILL.md 하나로 동작하며, 이 파일은 사람이 따로 보기 위한 사본이다.

## A1. 힉의 법칙 (Hick's Law)
선택지·정보가 많을수록 결정 시간이 늘어난다. (선택지가 익숙하고 정렬된 목록이면 영향이 줄어든다는 점도 고려)
- [ ] 한 화면의 동시 선택지가 과도한가(주요 행동 후보를 세어본다)
- [ ] 주요 행동과 보조 행동이 구분되는가
- [ ] 메뉴·필터·설정이 의미 단위로 묶여 있는가
- [ ] 지금 필요 없는 정보·옵션이 함께 노출되는가
- [ ] 단계별 공개, 기본값·추천값을 쓸 수 있는가

개선: 선택지 축소, 카테고리화, 단계별 공개(더보기·고급 설정·스텝), 추천값/기본값, 주요·부가 행동 분리(오버플로 메뉴 등)

## A2. 피츠의 법칙 (Fitts's Law)
목표까지의 거리가 멀고 크기가 작을수록 도달 시간과 오류가 늘어난다.
- [ ] 버튼·터치 영역이 충분한가(부록 B 기준)
- [ ] 자주 쓰는 기능이 가까운가(이전 동작 위치 기준)
- [ ] 인접 버튼 간격이 오작동을 막을 만큼인가
- [ ] 모바일에서 엄지로 조작하기 쉬운가
- [ ] 위험 행동이 주요 버튼과 너무 가까운가

개선: hit area 확대(시각 크기는 유지하고 padding만 늘리는 방법 포함), 주 버튼 위치 조정, 관련 컨트롤 근접 배치, 위험 행동 분리·확인 단계, 동선 단축

## A3. 제이콥의 법칙 (Jakob's Law)
사용자는 다른 서비스에서 익힌 방식대로 행동한다.
- [ ] 일반적인 UI 관습을 따르는가(로고=홈, 검색 위치, 장바구니 아이콘 등)
- [ ] 아이콘·버튼 의미를 예상할 수 있는가(라벨 없는 모호한 아이콘)
- [ ] 익숙한 기능을 불필요하게 새 방식으로 만들었는가
- [ ] 화면 간 내비게이션 규칙이 일관적인가
- [ ] 플랫폼 관례(iOS/Android/웹/콘솔)와 충돌하는가

개선: 익숙한 패턴 사용, 아이콘+텍스트 라벨, 내비게이션 통일, 플랫폼 표준 준수, 새 방식이 꼭 필요하면 온보딩·힌트·즉각 피드백

## A4. 근접성의 법칙 (Law of Proximity)
가까운 요소는 관련 있는 것으로 인식된다.
- [ ] 관련 정보가 시각적으로 묶여 있는가
- [ ] 무관한 요소가 너무 가까운가
- [ ] 섹션 간 간격 > 섹션 내부 간격이 명확한가
- [ ] 라벨·설명·입력창·오류 메시지의 관계가 분명한가(라벨이 위 입력창과 아래 입력창 사이 중간에 떠 있지 않은가)
- [ ] 카드·목록 경계가 구분되는가

개선: 관련 요소 간격 축소, 섹션 간격 확대, 그룹 컨테이너·배경, 간격 스케일 통일(예: 4/8/16/24/32), 정렬·계층 정리

## A5. 폰 레스토프 효과 (Von Restorff Effect)
여러 요소 중 다른 하나가 가장 잘 주목·기억된다.
- [ ] 가장 중요한 요소를 즉시 알 수 있는가(3초 응시 테스트)
- [ ] 동시에 강조된 요소가 너무 많은가
- [ ] 강조 색이 일관된 의미로 쓰이는가
- [ ] 주 CTA와 일반 버튼이 구분되는가
- [ ] 장식 요소가 핵심 정보보다 더 튀는가

개선: 화면당 핵심 강조 1개, 강조색은 주 CTA 전용, 보조 버튼 무게 낮추기(outline/텍스트 버튼), 크기·색·대비로 우선순위, 불필요한 배지·애니메이션 제거. 색만으로 구분하지 말 것(색각 이상 대응).
