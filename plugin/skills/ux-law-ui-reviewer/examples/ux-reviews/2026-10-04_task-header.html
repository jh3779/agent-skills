UX Law Review

작업 목록 헤더 (TaskHeader)

대상 프로젝트 관리 대시보드 · 작업 목록 상단 입력 React 코드 (TaskHeader.jsx, TaskHeader.css) 플랫폼 모바일·데스크톱 웹 공용 검토일 2026-10-04

01한줄 평가

"+ New Task"가 같은 파란색 버튼 6개 사이에 묻혀 있고 2px 옆에 "Delete All"이 붙어 있어, 새 작업을 만들기 어렵고 전체 삭제를 잘못 누를 위험이 있습니다.

02핵심 행동

핵심 행동

"+ New Task"로 새 작업 만들기

현재 발견 가능성
낮음

툴바 버튼 6개가 모두 .btn.primary라 구분되지 않고, 가장 먼저 눈에 띄는 건 깜빡이는 NEW·HOT 배지입니다.

방해 요소
  • 1초마다 깜빡이는 NEW/HOT 배지
  • 같은 강조색의 보조 버튼 4개
  • 생성 버튼에 붙은 Delete All
  • 항상 펼쳐진 필터 7개

가정 · 페이지 배경은 흰색, 기본 line-height 약 1.2로 계산. 부모 컴포넌트의 삭제 확인 단계는 확인하지 못했습니다.

03주요 문제

Critical

"+ New Task" 바로 옆에 같은 모양의 "Delete All"

피츠의 법칙폰 레스토프 효과
위치/요소
TaskHeader.jsx:16-17 · TaskHeader.css:6 (.toolbar gap: 2px)
왜 문제인가
가장 자주 누를 버튼과 되돌릴 수 없는 행동 사이가 2px이고, 색·크기도 같아 눈으로도 구분되지 않습니다. 컴포넌트 안에서 확인 단계 없이 바로 실행됩니다.
사용자 영향
새 작업을 만들려다 모든 작업을 지울 수 있습니다. 특히 모바일에서 위험합니다.
수정 방법
Delete All을 "⋯" 오버플로 메뉴로 옮기고, 작업 수를 보여주는 확인 단계를 페이지 안에 둡니다. 툴바에 남겨야 하면 반대쪽 끝에 빨간 텍스트 버튼으로 둡니다.
High

주 CTA가 다른 버튼과 구분되지 않음

폰 레스토프 효과힉의 법칙
위치/요소
TaskHeader.jsx:12-17 · btn primary 6회 사용
왜 문제인가
강조색이 6곳에 쓰여 아무것도 강조되지 않고, 생성 버튼은 7개 후보 중 다섯 번째에 있습니다.
사용자 영향
가장 중요한 행동을 찾는 시간이 늘어납니다.
수정 방법
.btn.primary는 "+ New Task"에만 남기고, Export·Import·Share·Archive는 "⋯ 더보기"로 묶습니다.
High

깜빡이는 NEW/HOT 배지가 시선을 빼앗음

폰 레스토프 효과법칙 외 · 접근성
위치/요소
TaskHeader.jsx:8-9 · TaskHeader.css:3-5 (animation: blink 1s infinite)
왜 문제인가
의미 없는 장식이 화면에서 유일하게 움직이고 가장 튀며, 멈출 방법이 없습니다(WCAG SC 2.2.2). 흰 글자 대비는 #ff2d55 3.65:1, #ff9500 2.2:1로 기준 4.5:1 미달입니다(SC 1.4.3).
사용자 영향
핵심 행동보다 장식에 주의가 먼저 갑니다.
수정 방법
의미가 없으면 배지를 지웁니다. 필요하면 "새 작업 3"처럼 구체적 문구로 바꾸고 애니메이션을 없앱니다.
High

포커스 표시 제거, 설정 아이콘에 키보드 접근 불가

법칙 외 · 접근성
위치/요소
TaskHeader.css:13 (button:focus { outline: none }) · TaskHeader.jsx:18 (div.icon onClick)
왜 문제인가
키보드 사용자는 포커스 위치를 볼 수 없고(SC 2.4.7), ⚙는 div라 Tab으로 갈 수 없으며 라벨도 없습니다.
사용자 영향
설정에 갈 수 없고, Tab 이동 중 Delete All을 누를 위험이 커집니다.
수정 방법
13행을 지우고 :focus-visible 스타일을 추가합니다. ⚙는 <button aria-label="설정">으로 바꿉니다.
Medium

버튼 클릭·터치 영역이 너무 작음

피츠의 법칙
위치/요소
TaskHeader.css:7 (.btn padding: 4px 6px; font-size: 12px)
왜 문제인가
버튼 높이 약 22px(추정)로 WCAG 2.2 SC 2.5.8 최소 24px에 못 미치고, 간격 2px라 간격 예외도 적용되지 않습니다.
사용자 영향
모바일에서 오조작이 잦고, 위 Critical 문제의 위험을 키웁니다.
수정 방법
.btn { min-height: 44px; padding: 8px 12px } (SC 2.5.5, Apple HIG), 툴바 gap: 8px(경험칙).
Medium

필터 라벨과 선택 상자가 떨어져 있고 연결도 안 됨

근접성의 법칙힉의 법칙
위치/요소
TaskHeader.jsx:22-29 · TaskHeader.css:11 (color: #aaa)
왜 문제인가
라벨 3개가 몰려 있고 select 3개가 따로 이어져 짝을 알 수 없습니다. #aaa 라벨은 대비 2.32:1입니다.
사용자 영향
필터를 잘못 설정하거나 해석하는 데 시간이 걸립니다.
수정 방법
각 필터를 <label>상태 <select>로 묶고, Status·Assignee만 보이게 한 뒤 나머지는 "필터 더보기"로 접습니다. 라벨 색 #595959(7.0:1).

04UX 법칙별 점검표

법칙평가근거
힉의 법칙문제 있음같은 무게의 실행 후보 7개와 필터 7개가 한꺼번에 노출됩니다.
피츠의 법칙문제 있음버튼 높이 약 22px, 간격 2px, 생성 버튼과 전체 삭제가 붙어 있습니다.
제이콥의 법칙개선 필요"+ New Task" 문구는 관례적이지만, Delete All을 주 툴바에 두는 구조는 일반적이지 않습니다.
근접성의 법칙문제 있음필터 라벨이 해당 select와 떨어져 있고 영역 간격이 버튼 간격과 비슷합니다.
폰 레스토프 효과문제 있음강조 클래스 6곳, 가장 튀는 요소가 의미 없는 배지입니다.

잘 된 점 · "+ New Task" 문구가 기능을 분명히 말해 줍니다. ⚙를 뺀 실행 요소가 실제 <button>입니다.

05우선순위별 개선안

이번 버전에 꼭 필요한 것

  • Delete All을 오버플로 메뉴로 옮기고 확인 단계 추가
  • 강조 스타일을 "+ New Task"에만
  • 배지 깜빡임 제거
  • 포커스 표시 복구, ⚙를 button으로

다음 버전에서 개선해도 되는 것

  • 버튼 44px·간격 8px, 모바일 전용 툴바
  • 필터 라벨 연결과 접기
  • 대비 4.5:1 이상으로 정리

현재는 제외하는 것이 좋은 것

  • 상단 전체를 사이드바·커맨드 팔레트로 재설계 — 강조 정리와 위험 버튼 분리로 대부분 해결됨
