# 오답 재교육 절차

사용자가 틀린 문항 번호를 알려 주면 이 순서로 진행한다.

## 1. 공통 원인 찾기

틀린 문항들을 나란히 놓고 **하나의 오해로 설명되는지** 본다.

| 흔한 공통 원인 | 증상 |
|---|---|
| "기계(검색·검사)가 뜻을 이해한다" | 키워드 매칭, 글자 대조, 규칙 사전 문항을 함께 틀림 |
| "언제 하는가"를 섞음 (미리 vs 요청 시) | 준비 단계 작업을 요청 시점 작업으로 고름 |
| "누가 하는가"를 섞음 (LLM vs 규칙·기계) | 뜻 판단처럼 느껴지는 규칙 작업을 LLM으로 고름 |
| 결과로 원인을 추론 | "점수가 낮다 → 엔진이 약하다" (시험지·데이터를 먼저 안 봄) |
| 정정 전 설명이 남음 | 내가 처음에 틀리게 가르친 보기를 고름 |

공통 원인이 있으면 **그것부터 한 번에** 설명하고, 문항별로는 짧게 연결만 한다.

## 2. 설명 각도 바꾸기

같은 설명을 다시 하면 같은 곳에서 또 막힌다. 바꾸는 방법:

- **새 비유**: 오픈북 시험("펼친 3쪽 안에서만 답하라"), 식당(장보기·손질 vs 조리), Ctrl+F, 메뉴판(미리 만들고 주문 때는 보기만)
- **직접 판단시키기**: "이 질문 단어만 보고 사람인 당신이 정답을 맞힐 수 있나요?" — 스스로 결론에 도달하게 한다
- **반례 사고 실험**: "만약 이 단어가 10건에만 나왔다면?"
- **판단 기준 압축**: 두 번째로 틀린 개념은 질문 두 개짜리 판별법으로 만든다

## 3. 내 설명 점검

오답이 내 설명 순서나 정정 이력 때문일 수 있다.

- 처음 설명이 틀려서 정정한 적이 있으면 **"이건 제 설명 순서 탓이 큽니다"**라고 말하고, 처음 설명 / 정정된 설명을 표로 나란히 둔다.
- "기억할 한 줄"을 준다.

## 4. 재확인

- 서술형 2~3문항, **보기 없이**. 퀴즈와 숫자·상황을 바꾼다.
- 답을 받으면 결론과 이유를 따로 채점한다.
- 그래도 틀리면, 그 개념은 다음 평가에서 반드시 재출제 목록에 넣는다.

## 5. 기록

대화 안에서 다음 두 목록을 유지한다 (최종평가 출제에 쓴다).

- **오해 목록**: 개념 | 처음 틀린 시점 | 재교육 후 결과
- **정정 목록**: 내가 처음 한 설명 | 정정된 내용 | 정정 시점
