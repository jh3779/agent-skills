# 퀴즈 설계 (중간평가·최종평가)

cognitive-teacher로 학습지를 만들 때 문항을 이 규칙으로 쓴다. 학습지의 마크업·조립 규칙은 cognitive-teacher의 `references/writing-guide.md`를 따른다.

## 문항 구성

| 평가 | 문항 수 | 범위 | 본문 |
|---|---|---|---|
| 중간 | 8~10 | 지금까지의 마일스톤 + 곁가지 논의 | 한 장 요약 + 핵심 원칙 1개 + 퀴즈 |
| 최종 | 12 안팎 | 전체 + 수업 중 정정 사항 | 최종 정리표 + "바로잡은 것" 표 + 퀴즈 |

범위별 문항 수를 표로 먼저 정하고 쓴다 (예: 파이프라인 전체 2 / 엔진 1 3 / 엔진 2 3 / 추가 논의 2).

## 좋은 문항의 조건

1. **본문을 안 읽으면 못 맞히고, 억지 함정은 없다.**
2. **오답 보기는 실제 오해에서.** 이번 수업에서 사용자가 실제로 말한 틀린 이유, 헷갈렸던 용어, 내가 처음에 잘못 설명했다가 정정한 내용을 보기로 쓴다. 그럴듯한 오해가 아니면 변별력이 없다.
3. **"왜"를 묻는다.** 결과만 묻는 문항(무엇이 위인가)보다 이유를 고르게 하는 문항(왜 위인가)이 이해를 더 잘 가른다. 보기에 "결론은 맞지만 이유가 틀린" 선택지를 하나 넣는다.
4. **계산 문항은 숫자를 바꾼다.** 수업 예시와 같은 숫자를 쓰면 기억으로 맞힌다.
5. **역할·시점 구분 문항**: "다음 중 X가 하는 일은?", "질문할 때 하지 않는 일은?"처럼 부정형도 섞는다. 부정형은 헷갈리기 쉬우니 한 평가에 1~2개만.
6. **측정 vs 계획 구분 문항**을 하나 넣는다: "현재 실제로 측정된 것은?"
7. **해설**: 정답 이유 + 왜 대표 오답이 틀렸는지 + 본문 어느 절인지.

## 재출제 (최종평가, 재교육 후)

틀렸던 개념은 **같은 개념, 다른 표면**으로 다시 낸다.

| 원래 문항 | 재출제 방법 |
|---|---|
| 순위 1등·순위 밖 vs 5등·5등 | 2등·2등 vs 1등·40등 (계산이 덜 뻔하게) |
| 리콜 대상 차종 목록 문장 | 다른 비원인 문장, 또는 공백만 다른 경우와 비교 |
| 부품 그래프 "만들기" | 다른 미리 하는 작업(문서 임베딩, 역색인)으로 |

## 피해야 할 것

- 수업에서 다루지 않은 내용 출제
- 보기 길이로 정답이 티 나는 문항 (정답만 유독 긴 보기)
- 한 문항에 두 개념을 섞어 어느 쪽을 몰라서 틀렸는지 알 수 없는 문항
